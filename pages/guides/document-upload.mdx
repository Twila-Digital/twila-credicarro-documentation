Os documentos do comprador, do vendedor e da loja são enviados por `POST /v2/proposal/{propostaId}/document`, **um arquivo por chamada**.

## Quando enviar

| Etapa ativa do participante | O que enviar |
| --- | --- |
| `ENVIO_DOCUMENTOS` (6), com a proposta aprovada | Os documentos pedidos |
| `CORRECAO_DOCUMENTOS` (7), com a proposta pendente | Só os tipos com status `INVALIDO` |

Fora dessas etapas, a API retorna `422`.

<Note>
  Cada participante tem a sua etapa. Olhe o `status_ativo` de **cada** participante antes de enviar.
</Note>

## Regras do arquivo

- Formatos: PDF, JPG/JPEG ou PNG
- Até **10 MiB** depois de decodificado
- `nomeArquivo` com extensão, sem caminho, até 255 caracteres
- A extensão precisa corresponder ao conteúdo real do arquivo
- `conteudoBase64` em Base64 puro, **sem** o prefixo `data:application/pdf;base64,`
- Header `Idempotency-Key` **obrigatório**

## Exemplo

```bash
curl -X POST https://api.staging.credicarro.com.br/integration/v2/proposal/{propostaId}/document \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7c9e6679-7425-40de-944b-e07fc1f90ae7" \
  -d '{
    "participante": "COMPRADOR",
    "tipoDocumento": 1,
    "nomeArquivo": "cnh-comprador.pdf",
    "conteudoBase64": "JVBERi0xLjcKJcOkw7zDtsOfCjIgMCBvYmoK..."
  }'
```

Para montar o `conteudoBase64`, leia os bytes do arquivo e codifique em Base64 padrão, sem quebras de linha e sem o prefixo `data:`.

Gere a chave uma vez por envio — por exemplo, um UUID salvo junto ao registro do documento no seu sistema — e passe a mesma chave em todas as tentativas desse envio.

Resposta: `204 No Content`, sem corpo. O documento entra com status `RECEBIDO` e passa por análise. Um novo envio do mesmo tipo e participante substitui o anterior.

<Warning>
  Gere a `Idempotency-Key` **uma vez por envio** e reaproveite a mesma chave nas retentativas desse envio. Com a mesma chave e o mesmo conteúdo, um envio bem-sucedido nas últimas 24 horas não é processado de novo. Uma chave nova a cada tentativa reenvia e substitui o documento.
</Warning>

## Correção de documentos

Quando um documento é recusado, o participante vai para `CORRECAO_DOCUMENTOS` e o documento aparece com `status` = `INVALIDO` e o `motivo`:

```json
{
  "status_ativo": {
    "enum_etapa": 7,
    "etapa": "CORRECAO_DOCUMENTOS",
    "enum_situacao": 4,
    "situacao": "PENDENTE_CORRECAO",
    "enum_responsavel_acao": 2,
    "responsavel_acao": "INTEGRADOR"
  },
  "documentos": [
    { "enum_tipo": 1, "tipo": "CNH", "enum_status": 2, "status": "INVALIDO", "motivo": "Documento ilegível" },
    { "enum_tipo": 5, "tipo": "COMPROVANTE_RESIDENCIA", "enum_status": 1, "status": "VALIDO" }
  ]
}
```

<Steps>
  <Step title="Filtre os recusados">
    Selecione os documentos com `enum_status` = 2 (`INVALIDO`).
  </Step>
  <Step title="Mostre o motivo">
    Exiba o `motivo` para a loja ou o cliente corrigir o arquivo.
  </Step>
  <Step title="Reenvie o mesmo tipo">
    Envie de novo com o mesmo `participante` e `tipoDocumento`, com uma **nova** `Idempotency-Key`. Enviar um tipo que não está recusado retorna `422`.
  </Step>
</Steps>

## Erros

Erros de formato retornam `400`, com o campo em `campo`:

| `tipo` | Como resolver |
| --- | --- |
| `Validation.Field.Required` | Envie o campo indicado em `campo` (inclusive o header `Idempotency-Key`). |
| `Validation.IdempotencyKey.Invalid` | Use uma `Idempotency-Key` de 1 a 200 caracteres. |
| `Validation.Field.InvalidOption` | Use `COMPRADOR`, `VENDEDOR` ou `LOJA` e um `tipoDocumento` da tabela. |
| `Validation.Document.TypeNotAllowed` | O tipo não é aceito para o participante. Confira a tabela. |
| `Validation.File.InvalidName` | Use só o nome do arquivo, sem caminho, com até 255 caracteres. |
| `Validation.File.InvalidExtension` | Use `.pdf`, `.jpg`, `.jpeg` ou `.png`. |
| `Validation.File.InvalidBase64` | Remova o prefixo `data:` e quebras de linha. |
| `Validation.File.Empty` | O arquivo está vazio. |
| `Validation.File.TooLarge` | Comprima ou reduza a resolução do arquivo. |

Regras que dependem da proposta retornam `422`:

| Situação | Como resolver |
| --- | --- |
| A etapa ativa não permite envio | Aguarde a etapa `ENVIO_DOCUMENTOS` ou `CORRECAO_DOCUMENTOS`. |
| Na correção, o tipo enviado não está recusado | Reenvie só os tipos com status `INVALIDO`. |
| O conteúdo não corresponde à extensão | Não renomeie arquivos de outro formato. |
| A `Idempotency-Key` já foi usada com outro conteúdo | Use uma nova chave para um novo envio. |
