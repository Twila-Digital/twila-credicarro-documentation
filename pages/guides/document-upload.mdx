Os documentos do comprador e da loja são enviados por `POST /v2/proposal/{propostaId}/document`, **um arquivo por chamada**.

## Quando enviar

| Etapa ativa do participante | O que enviar |
| --- | --- |
| `ENVIO_DOCUMENTOS` (6), com a proposta aprovada | Os documentos pedidos |
| `CORRECAO_DOCUMENTOS` (7) | Só os tipos com status `INVALIDO` |

Fora dessas etapas, a API retorna `Document.InvalidProposalStage`.

<Note>
  O comprador e a loja têm etapas separadas. Olhe o `status_ativo` de **cada** participante antes de enviar.
</Note>

## Tipos aceitos

| Código | Tipo | Comprador | Loja |
| --- | --- | :---: | :---: |
| 1 | `CNH` | ✓ | |
| 4 | `COMPROVANTE_RENDA` | ✓ | |
| 5 | `COMPROVANTE_RESIDENCIA` | ✓ | |
| 6 | `DOCUMENTO_VEICULO` | ✓ | ✓ |
| 7 | `CNH_DIGITAL` | ✓ | |
| 8 | `LAUDO_ECV` | | ✓ |
| 9 | `LAUDO_VISTORIA` | ✓ | |
| 57 | `ATPV` | ✓ | |

## Regras do arquivo

- Formatos: PDF, JPG/JPEG ou PNG
- Até **10 MiB** depois de decodificado
- `nomeArquivo` com extensão, sem caminho, até 255 caracteres
- A extensão precisa corresponder ao conteúdo real do arquivo
- `conteudoBase64` em Base64 puro, **sem** o prefixo `data:application/pdf;base64,`
- Header `Idempotency-Key` **obrigatório**

## Exemplo

```bash
curl -X POST https://api.staging.credicarro.com.br/integration/v2/proposal/{propostaId}/document \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7c9e6679-7425-40de-944b-e07fc1f90ae7" \
  -d '{
    "participante": "COMPRADOR",
    "tipoDocumento": 1,
    "nomeArquivo": "cnh-comprador.pdf",
    "conteudoBase64": "JVBERi0xLjcKJcOkw7zDtsOfCjIgMCBvYmoK..."
  }'
```

Para montar o `conteudoBase64`, leia os bytes do arquivo e codifique em Base64 padrão, sem quebras de linha e sem o prefixo `data:`.

Gere a chave uma vez por envio — por exemplo, um UUID salvo junto ao registro do documento no seu sistema — e passe a mesma chave em todas as tentativas desse envio.

Resposta: `200 OK`, sem corpo. O documento entra com status `RECEBIDO` e passa por análise.

<Warning>
  Gere a `Idempotency-Key` **uma vez por envio** e reaproveite a mesma chave nas retentativas desse envio. Uma chave nova a cada tentativa pode registrar o documento duas vezes; a mesma chave com outro arquivo retorna `Idempotency.KeyConflict`.
</Warning>

## Correção de documentos

Quando um documento é recusado, o participante vai para `CORRECAO_DOCUMENTOS` e o documento aparece com `status` = `INVALIDO` e o `motivo`:

```json
{
  "status_ativo": {
    "enum_etapa": 7,
    "etapa": "CORRECAO_DOCUMENTOS",
    "enum_situacao": 4,
    "situacao": "PENDENTE_CORRECAO",
    "enum_responsavel_acao": 2,
    "responsavel_acao": "INTEGRADOR"
  },
  "documentos": [
    { "enum_tipo": 1, "tipo": "CNH", "enum_status": 2, "status": "INVALIDO", "motivo": "Documento ilegível" },
    { "enum_tipo": 5, "tipo": "COMPROVANTE_RESIDENCIA", "enum_status": 1, "status": "VALIDO", "motivo": null }
  ]
}
```

<Steps>
  <Step title="Filtre os recusados">
    Selecione os documentos com `enum_status` = 2 (`INVALIDO`).
  </Step>
  <Step title="Mostre o motivo">
    Exiba o `motivo` para a loja ou o cliente corrigir o arquivo.
  </Step>
  <Step title="Reenvie o mesmo tipo">
    Envie de novo com o mesmo `participante` e `tipoDocumento`, com uma **nova** `Idempotency-Key`. Enviar um tipo que não está recusado retorna `Document.NotPendingCorrection`.
  </Step>
</Steps>

## Erros

| Código | Como resolver |
| --- | --- |
| `Document.InvalidParticipant` | Use `COMPRADOR` ou `LOJA`. |
| `Document.InvalidType` | Confira a tabela de tipos por participante. |
| `Document.InvalidName` | Use só o nome do arquivo, com extensão `.pdf`, `.jpg`, `.jpeg` ou `.png`. |
| `Document.InvalidBase64` | Remova o prefixo `data:` e quebras de linha. |
| `Document.Empty` | O arquivo está vazio. |
| `Document.TooLarge` | Comprima ou reduza a resolução do arquivo. |
| `Document.InvalidContent` | A extensão não corresponde ao conteúdo. Não renomeie arquivos de outro formato. |
| `Document.InvalidProposalStage` | Aguarde a etapa `ENVIO_DOCUMENTOS` ou `CORRECAO_DOCUMENTOS`. |
| `Document.NotPendingCorrection` | Na correção, reenvie só os tipos com status `INVALIDO`. |
| `Idempotency.KeyConflict` | Use uma nova chave para um novo envio. |
