## <Icon icon="shield-halved" type="solid"/> Tipos de Autenticação

Aceitamos três tipos de autenticação para os webhooks (`tipo_autenticacao`). O tipo e a credencial não podem ser alterados depois do cadastro; para trocá-los, exclua o webhook e cadastre outro.

<Card title="1 - Sem Autenticação (Não recomendado)" icon="triangle-exclamation" horizontal color="#ef4444">
  Se o seu endpoint não requer autenticação, você pode optar por não usar nenhum método de autenticação. Nesse caso, as notificações serão enviadas para o seu endpoint sem nenhum cabeçalho de autenticação.
</Card>

<Card title="2 - Basic" icon="user-lock" color="#25c2a0" horizontal>
  Informe em `credencial` o valor em Base64 de `usuario:senha`. Cada notificação é enviada com o header `Authorization: Basic {credencial}`.
</Card>

<Card title="3 - Bearer JWT" icon="id-card" color="#25c2a0" horizontal>
  Informe em `credencial` o token. Cada notificação é enviada com o header `Authorization: Bearer {credencial}`.
</Card>

## <Icon icon="envelope-open-text" type="solid"/> Como a notificação é enviada

Cada notificação é um `POST` com corpo JSON (`Content-Type: application/json`) e os headers:

| Header | Conteúdo |
| --- | --- |
| `Authorization` | Conforme o tipo de autenticação do webhook (ausente quando for 1 - Sem Autenticação). |
| `X-CrediCarro-Signature` | Assinatura HMAC do corpo, no formato `t={timestamp},v1={assinatura}`. |
| `Idempotency-Key` | Identificador da notificação. Retentativas da mesma notificação repetem a chave. |

## <Icon icon="signature" type="solid"/> Validar a assinatura

O `segredo_assinatura` é retornado uma única vez, no cadastro do webhook. Para validar uma notificação:

<Steps>
  <Step title="Leia o header">
    Separe `t` (timestamp Unix em segundos) e `v1` (assinatura em hexadecimal minúsculo) do header `X-CrediCarro-Signature`.
  </Step>
  <Step title="Monte o conteúdo assinado">
    Concatene o valor de `t`, um ponto (`.`) e o corpo da requisição exatamente como recebido, sem reformatar o JSON.
  </Step>
  <Step title="Calcule e compare">
    Calcule o HMAC-SHA256 desse conteúdo usando o `segredo_assinatura` como chave e compare com `v1` usando uma comparação de tempo constante. Recuse também timestamps muito antigos para evitar reenvios maliciosos.
  </Step>
</Steps>

```javascript
import crypto from "node:crypto";

function assinaturaValida(rawBody, header, segredo) {
  const partes = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const esperado = crypto
    .createHmac("sha256", segredo)
    .update(`${partes.t}.${rawBody}`)
    .digest("hex");
  return crypto.timingSafeEqual(Buffer.from(esperado), Buffer.from(partes.v1));
}
```

## <Icon icon="rotate" type="solid"/> Respostas e retentativas

<Card title="Responda com 2xx" icon="check" horizontal>
  - Qualquer resposta `2xx` confirma o recebimento.
  - Respostas `408`, `425`, `429` e `5xx`, falhas de rede e tempo esgotado (15 segundos) são retentadas automaticamente.
  - As demais respostas `4xx` não são retentadas.
  - Responda rápido e processe a notificação de forma assíncrona; trate notificações repetidas pelo `Idempotency-Key`.
</Card>

## <Icon icon="code" type="solid"/> Payload do Webhook (propostas v1)

O payload enviado para o endpoint do webhook é um JSON com a seguinte estrutura:

```json
{
  "id_proposta": "00000000-0000-0000-0000-000000000000",
  "enum_status": 1,
  "status": "Analysing"
}
```
