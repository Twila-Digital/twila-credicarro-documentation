## Em uma frase

A API da Credicarro é REST, autenticada por Bearer token, com campos JSON em português e o mesmo formato de resposta em toda a superfície — um cliente HTTP e um token já bastam para integrar.

<Card title="Não é a página de referência de endpoints" icon="circle-info" horizontal>

</Card>

## Ambientes

| Ambiente | Base URL | Uso |
| --- | --- | --- |
| Staging | `https://api.staging.credicarro.com.br/integration` | Testes, sem afetar produção — veja [ambiente de desenvolvimento](/pages/development) |
| Produção | `https://api.credicarro.com.br/integration` | Propostas reais |

O ambiente é determinado pela URL base que você chama — as credenciais (`ClientId`/`ClientSecret`) são específicas de cada ambiente.

## Autenticação

Toda requisição autenticada usa um Bearer token, obtido via `ClientId`/`ClientSecret` solicitados ao nosso suporte.

```bash
curl -X POST https://api.staging.credicarro.com.br/integration/v1/authentication/accesstoken \
  -H "Content-Type: application/json" \
  -d '{ "clientId": "<client-id>", "clientSecret": "<client-secret>" }'
```

## Formato das respostas

Os campos JSON são em português. Listas paginadas seguem sempre o mesmo formato:

```json
{
  "itens": [ ],
  "pagina": {
    "numero": 1,
    "tamanho": 10,
    "total": 45,
    "tem_proximo": true,
    "tem_anterior": false
  }
}
```

## Erros

As respostas de erro trazem os campos `tipo` (código estável do erro), `titulo`, `status` e `detalhe`. Quando o erro é de um campo, vem também `campo`. As exceções são o `401`, que vem sem corpo, e falhas inesperadas, que podem vir no formato padrão Problem Details.

## Idempotência

As rotas de cliente, simulação, proposta e documento aceitam o cabeçalho `Idempotency-Key`: reenviar a mesma chave com o mesmo corpo retorna o resultado original em vez de repetir a operação. No [envio de documentos](/pages/v2/proposal/document) o cabeçalho é obrigatório.

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 Unauthorized" icon="lock">
    O token não foi enviado, é inválido ou expirou. Gere um novo token — veja [Autenticação](/pages/authentication).
  </Accordion>
  <Accordion title="404 em uma proposta que existe" icon="magnifying-glass">
    A proposta pode pertencer a outro parceiro, ou o token pode ser de outro ambiente (staging x produção).
  </Accordion>
  <Accordion title="409 Conflict em POST" icon="ban">
    Uma `Idempotency-Key` já usada com um corpo diferente. Gere uma nova chave para uma nova operação — veja [Erros e idempotência](/pages/errors).
  </Accordion>
  <Accordion title="404 ou 422 na simulação" icon="store">
    `404` (`Store.Integration.NotFound`): o `cnpjLoja` não existe ou não está vinculado ao seu cadastro de parceiro. `422` (`Store.Integration.Intermediation`): a loja tem contrato de intermediação e não pode ser usada na integração.
  </Accordion>
</AccordionGroup>

## Boas práticas de segurança

<Card icon="shield-halved" horizontal>
  * Armazene `ClientId`/`ClientSecret` em variáveis de ambiente ou um gerenciador de segredos — nunca no código-fonte
  * Nunca exponha o `ClientSecret` em código client-side (app mobile, SPA)
  * A Credicarro nunca solicita suas credenciais por e-mail ou telefone
</Card>
