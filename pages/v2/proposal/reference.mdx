A **proposta** é o pedido de crédito, criado a partir de uma opção de simulação. Ela traz o status geral e, para cada participante (comprador, loja e, quando houver, vendedor), a etapa ativa e quem precisa agir.

## Ciclo de vida

```mermaid
flowchart LR
    A[Simulação] -->|POST /v2/proposal| B[EM_ANALISE]
    B --> C[APROVADA]
    B --> R[RECUSADA]
    B --> M[ANALISE_MANUAL]
    M --> C
    M --> R
    C -->|formalização| F[FINALIZADA]
    C --> X[CANCELADA / EXPIRADA]
```

O diagrama mostra os caminhos mais comuns. A lista completa de status está em [Etapas e status](/pages/v2/steps).

## Endpoints

| Endpoint | Quando chamar |
| --- | --- |
| [`POST /v2/proposal`](/pages/v2/proposal/create) | Criar a proposta com o `id_simulacao` escolhido. |
| [`GET /v2/proposal/{propostaId}`](/pages/v2/proposal/get) | Consultar o retrato atual. |
| [`POST /v2/proposal/{propostaId}/document`](/pages/v2/proposal/document) | Etapa `ENVIO_DOCUMENTOS` ou `CORRECAO_DOCUMENTOS`. |
| [`POST /v2/proposal/{propostaId}/vehicle-detail`](/pages/v2/proposal/vehicle-detail) | Etapa `DADOS_VEICULO`. |
| [`POST /v2/proposal/{propostaId}/deposit-account`](/pages/v2/proposal/deposit-account) | Etapa `CONTA_RECEBIMENTO` do comprador (só refinanciamento). |
| [`POST /v2/proposal/{propostaId}/seller/notification`](/pages/v2/proposal/seller-notification) | Etapa `NOTIFICACAO_VENDEDOR` da loja, com notificação pela Credicarro (intermediação). |
| [`POST /v2/proposal/{propostaId}/seller`](/pages/v2/proposal/seller) | Etapa `NOTIFICACAO_VENDEDOR` da loja (intermediação). |
| [`POST /v2/proposal/{propostaId}/seller/decision`](/pages/v2/proposal/seller-decision) | Etapa `ACEITE_VENDEDOR`, com notificação própria (intermediação). |
| [`POST /v2/proposal/{propostaId}/seller/deposit-account`](/pages/v2/proposal/seller-deposit-account) | Etapa `CONTA_RECEBIMENTO` do vendedor (intermediação). |
| [`POST /v2/proposal/{propostaId}/seller/company`](/pages/v2/proposal/seller-company) | Etapa `DADOS_EMPRESA` do vendedor lojista (intermediação). |
| [`GET /v1/proposal`](/pages/proposal/pagination) | Listar as propostas do parceiro. |

## Objeto proposta

```json GET /v2/proposal/{propostaId}
{
  "id_proposta": "bea8d060-f93d-48eb-b6c4-45f64483cdd9",
  "numero": 171020250001,
  "id_simulacao": "123e4567-e89b-12d3-a456-426614174000",
  "enum_status": 2,
  "status": "APROVADA",
  "tipo": "Financing",
  "data_criacao": "2026-10-12T14:05:08.984-03:00",
  "link_biometria": "https://onboarding.exemplo.com/sessao/abc123",
  "comprador": {
    "cpf": "12345678909",
    "enum_biometria": 1,
    "biometria": "SESSAO_CRIADA",
    "status_ativo": {
      "enum_etapa": 4,
      "etapa": "ANALISE_BIOMETRIA",
      "enum_situacao": 2,
      "situacao": "AGUARDANDO_CLIENTE",
      "enum_responsavel_acao": 1,
      "responsavel_acao": "CLIENTE"
    },
    "etapas_concluidas": [
      { "enum_etapa": 1, "etapa": "PROPOSTA_CRIADA", "data": "2026-10-12T14:05:08-03:00" },
      { "enum_etapa": 2, "etapa": "PROPOSTA_APROVADA", "data": "2026-10-12T14:06:40-03:00" }
    ],
    "documentos": []
  },
  "loja": {
    "cnpj": "11222333000181",
    "status_ativo": {
      "enum_etapa": 6,
      "etapa": "ENVIO_DOCUMENTOS",
      "enum_situacao": 1,
      "situacao": "AGUARDANDO_ENVIO",
      "enum_responsavel_acao": 2,
      "responsavel_acao": "INTEGRADOR"
    },
    "etapas_concluidas": [],
    "documentos": []
  },
  "intermediacao": false
}
```

| Campo | Descrição |
| --- | --- |
| `id_proposta` | Identificador da proposta. |
| `numero` | Número da proposta, útil para atendimento. |
| `id_simulacao` | Simulação que originou a proposta. |
| `enum_status` / `status` | Status geral. Veja [Etapas e status](/pages/v2/steps). |
| `tipo` | `Financing` (financiamento) ou `Refinancing` (refinanciamento). |
| `data_criacao` | Data de criação. |
| `motivo_recusa` | Motivo da recusa. Omitido quando vazio. |
| `link_biometria` | Link para o cliente fazer a biometria. A Credicarro já envia esse link ao cliente, exceto quando a integração conduz o contato. Omitido quando vazio. |
| `comprador` | Biometria, etapa ativa, etapas concluídas e documentos do comprador. |
| `vendedor` | Vendedor da [intermediação](/pages/guides/intermediation-integration): a estrutura de `comprador`, mais os campos da tabela abaixo. Omitido quando a proposta não tem vendedor. |
| `loja` | Etapa ativa, etapas concluídas e documentos da loja. Omitido quando a proposta não foi feita em loja. |
| `intermediacao` | `true` quando a proposta é de intermediação, com um vendedor terceiro. |

Campos do `vendedor`, além dos de `comprador`. Os campos vazios são omitidos:

| Campo | Descrição |
| --- | --- |
| `tipo_pessoa` | `FISICA` (pessoa física) ou `JURIDICA` (lojista). |
| `cpf` | CPF do vendedor pessoa física. |
| `cnpj` | CNPJ do lojista. |
| `decisao` | `INFORMADO` enquanto o vendedor não decide, `ACEITO` ou `RECUSADO`. |
| `data_decisao` | Data da decisão do vendedor. |
| `link_biometria` | Link para o vendedor pessoa física fazer a biometria. Na notificação própria, repasse esse link ao vendedor. |
| `empresa` | `razao_social`, `nome_fantasia`, `cnpj` e `data_abertura` do lojista, depois da etapa `DADOS_EMPRESA`. |

## Como decidir o próximo passo

Para **cada** participante (`comprador`, `vendedor` e `loja`), leia `status_ativo`:

| `responsavel_acao` | `etapa` | O que fazer |
| --- | --- | --- |
| `INTEGRADOR` (2) | `ENVIO_DOCUMENTOS` (6) ou `CORRECAO_DOCUMENTOS` (7) | [Enviar documento](/pages/v2/proposal/document) |
| `INTEGRADOR` (2) | `DADOS_VEICULO` (8) — da loja no financiamento, do comprador no refinanciamento, do vendedor na intermediação | [Incluir dados do veículo](/pages/v2/proposal/vehicle-detail) |
| `INTEGRADOR` (2) | `CONTA_RECEBIMENTO` (5) — do comprador | [Incluir conta de recebimento](/pages/v2/proposal/deposit-account) |
| `INTEGRADOR` (2) | `CONTA_RECEBIMENTO` (5) — do vendedor | [Incluir conta de recebimento do vendedor](/pages/v2/proposal/seller-deposit-account) |
| `INTEGRADOR` (2) | `NOTIFICACAO_VENDEDOR` (3) — da loja | [Pedir a notificação do vendedor](/pages/v2/proposal/seller-notification) ou [Informar o vendedor](/pages/v2/proposal/seller) |
| `INTEGRADOR` (2) | `DADOS_EMPRESA` (14) — do vendedor lojista | [Incluir dados da empresa do vendedor](/pages/v2/proposal/seller-company) |
| `CLIENTE` (1) | `ACEITE_VENDEDOR` (13) — do vendedor | Na notificação própria, [Registrar a decisão do vendedor](/pages/v2/proposal/seller-decision). Na notificação pela Credicarro, aguardar o vendedor |
| `CLIENTE` (1) | demais etapas | Orientar o cliente ou o vendedor (biometria, vistoria ou assinatura) |
| `CREDICARRO` (3) | qualquer | Aguardar |
| `NENHUM` (0) | qualquer | Nada — a proposta foi encerrada |

<Tip title="Compare pelo número" horizontal>
  No seu sistema, prefira comparar `enum_etapa` e `enum_responsavel_acao` e usar os nomes em telas e logs.
</Tip>
